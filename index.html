A true-enough story of AI security

Every AI breach begins politely.

No malware. No exploit code. Just language, aimed at a machine that treats language as instructions. Scroll through how an agentic AI incident actually unfolds — and meet the person writing the playbook for what comes after.

Incident narrative · composite of real cases

How it actually happens

T+00:00:00

A document arrives.

It lands in a shared inbox. No macros. No suspicious links. No payload a scanner would recognize. Just prose — and folded inside the prose, instructions written for a reader that isn't human. It gets indexed into the company knowledge base, like everything else. Then it waits.

T+06:12:00

Someone asks a question.

Six hours later, an employee asks the AI assistant something ordinary. The pipeline does exactly what it was built to do: embed the query, search the vector store, retrieve the best-matching chunks. The planted document scores beautifully. It was engineered to.

T+06:12:02

The model reads.

It reads retrieved context the way it reads everything: as language. Inside a transformer, there is no hard boundary between the data it was given and the instructions it was given. The hidden text doesn't hack the model. It just asks. Politely.

T+06:12:03

A tool call fires.

The assistant has tools — it can fetch, render, send. One call goes out to an external URL whose parameters happen to encode the contents of the user's private files. To every control on the network, it is indistinguishable from the assistant doing its job. Which, technically, it is.

T+??:??:??

Then — nothing.

No malware to detect. No CVE in your stack to patch. No process tree to kill. The attack was a paragraph, and it executed on a model, not a machine. The EDR saw nothing because there was nothing to see. Classic incident response was built for a different kind of breach. So the clock just… runs.
